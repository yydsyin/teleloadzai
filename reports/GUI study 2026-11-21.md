## What we already do as well or better

| Point | Them | Teleloadzai |
|---|---|---|
| Download reuses the card's reading (`--load-info-json`) | only ytDownloader (`renderer.js:2935`: 1 h, one retry from the link) | **yes since today**: 20 min, used once, one retry from the link on 403/404/410 |
| Pieces in parallel (`--concurrent-fragments`) | off by default everywhere (ytDownloader 1–16, Seal > 1 only); Parabolic only with aria2c | **4 by default** (measured 2× on Dailymotion / TED) |
| Errors explained | Open Video Downloader: a rules file, ~33 codes, each with a way out (`diagnostic_rules.json`); Media Downloader: 6–7 named errors (`yt-dlp.cpp:1415`); the others show raw text | `explain.py`: only errors really seen, with evidence (decision 38), raw words under them |
| Filters, failed count, Retry all failed | Parabolic (`MainWindow.xaml.cs:503`) | yes |
| Per-row log | Parabolic (expandable log) | Details + the Console |
| Card shown at once while reading | Open Video Downloader (URL as title, bar with no value); the others block with a spinner or a dialog | yes, and since today shimmering shapes + "Best" ready |
| A list that survives closing | Seal (`encodeTaskListBackup`) | yes (`data/jobs.json`) |

## What they do that we don't — the decision for each

| # | Idea | Who, where | Decision | Why |
|---|---|---|---|---|
| 1 | **Download pressed during the reading: the row appears at once** in the list ("Reading the link…") and the card is free for the next link; the download starts by itself when the reading ends | Seal (`downloadWithPreset` → `enqueue`, the task reads in its row), Media Downloader (`batchdownloader.cpp:752`, row first, filled later) | **TAKE** | Today the button says "Waiting for the title…" and the card is held 2–25 s. The row appearing at once is the biggest "feels fast" left — and with today's reuse, the download then starts in ~1 s. |
| 2 | **An approximate size beside each quality** ("720p · ~45 MB") | ytDownloader (`renderer.js:3460`: `filesize`, else `filesize_approx`, else duration × `tbr`, "~" when estimated, "unknown" when none); Open Video Downloader (a second run per format) | **TAKE** (ytDownloader's way) | The card's reading already holds these numbers: no extra run, no wait. The user sees what each choice costs. |
| 3 | **"Copy report" on a failed row**: version + link + the program's washed words, one click | Seal (ErrorPage "Copy error report"), ytDownloader (click-to-copy details) | **TAKE** | Our Details shows the words "for a bug report" but copying means selecting by hand. The washing (decision 37) stays. |
| 4 | Download on paste, no card ("auto mode", "download immediately") with the last choices | Parabolic (`PreviousDownloadImmediatelyAsVideo`), ytDownloader (`isAutoMode`), cobalt, Seal presets | **LATER** | Useful for repeat users, but it fights the "Save as" window (decision 22, on by default) and skips the warnings the card gives (log-in, a program that fails). A setting, off by default, after 1–3. |
| 5 | Progress on the app's icon in the Windows taskbar | ytDownloader (Electron `setProgressBar`) | **LATER** | Nice when the window is behind others; needs Windows' taskbar functions through ctypes — to be proven in pywebview first. |
| 6 | A reading that fails fast (`--socket-timeout 5 -R 1`) and a Cancel that ends it | Seal (`DownloadUtil.kt` ~L176) | **LATER, measure first** | Our reading waits up to 60 s when the network is gone. But a 5 s socket limit may break slow sites (Bilibili took 25 s once today). |
| 7 | aria2c as an external downloader (`-x 16 -k 20M`) | Parabolic, Media Downloader, Seal — all optional | **NO** | A new program "just in case" (decision 4); our measured default already doubles HLS sites, and the others' default is slower than ours. |
| 8 | Pause / Resume | Open Video Downloader, Parabolic | **NO** | Stop + Continue already resume (Continue resumed at 83.5 %, 2026-11-01). |
| 9 | Keyboard shortcuts beyond Ctrl+Enter, haptic ticks | cobalt | **NO** | The user's rule "no useless shortcuts"; haptics: no desktop equivalent. |

## Recommended order

1 → 2 → 3, each drawn first (models), then built and checked at the two window sizes.

# Part 2 — the WHOLE GUI of the 6 apps, and the defects of ours (2026-11-21, later)

The user: "study all of them, not one part — what are the defects of our GUI". Every screen of each app was listed (main window, pages, settings sections, dialogs, first run, about, tray, notifications), then compared with ours. A "we lack it" counts only after a search of our code; each one below was searched again by me, with control searches that must hit (Retry failed 4, Clear finished 7, prefers-color-scheme 2), so a 0 is a real absence.

## Defects of our GUI, verified

| # | Defect (what a user meets) | Who does better (their file) | Our search | Size |
|---|---|---|---|---|
| 1 | A playlist or a batch of links downloads **every** video: no way to tick only some | Seal `PlaylistSelectionPage.kt` (Select all), Parabolic Items tab, Media Downloader playlist table, cobalt picker | `openPlaylist` adds all entries; "Select all" / checkbox / remove-one-link in the card: 0 | medium-big |
| 2 | **No search** in a list of up to 500 downloads | Parabolic `HistoryDialog.xaml` (search + sort), Seal "Search in downloads", ytDownloader history | search box: 0 | medium |
| 3 | **No About**: the app's version is never shown, no "report a problem", no check for a new Teleloadzai | all six (Parabolic About + Report a bug + Check for updates; Seal, cobalt changelog) | About / version in the page: 0 (the version exists only in `config.py`) | medium |
| 4 | **No "Stop all"** — 20 running rows mean 20 Stops | Parabolic "Stop all remaining" + "Clear queued" | 0 | medium |
| 5 | **Audio only as MP3** — no M4A, Opus, FLAC | ytDownloader Media Settings, Open Video Downloader encoding options | other audio formats: 0 | medium |
| 6 | **Settings is one flat page**: no theme choice (Windows decides), no "Reset to defaults" | all six group settings in sections; theme choice in five; cobalt / Seal export, import, reset | theme control: 0; reset: 0 | medium |
| 7 | **No drag-and-drop** of a link onto the window | Open Video Downloader `DragDropOverlay.vue`, cobalt `DropReceiver.svelte` | drop handlers: 0 | small-medium |
| 8 | **No one-click copy** of a row's link or of a failure's report | Seal "Copy link", "Copy error report" (version + link + message) | "Copy link": 0; copy exists only in the Console | small |
| 9 | A **running** row shows no raw words; Details exists only on failed rows (the Console has them) | Parabolic "Show log" on every row | Details on a running row: 0 | small |
| 10 | **No high-contrast support** (Windows contrast themes) | cobalt Accessibility page, Seal high contrast | forced-colors / prefers-contrast: 0 | small |

From Part 1, still valid: the row appears at once when Download is pressed during the reading (Seal, Media Downloader), and an approximate size beside each quality (ytDownloader).

## Not defects — decided or parked by the user (CLAUDE.md)

Time-range cut, SponsorBlock, speed limit, proxy, scheduler / subscriptions, filename templates, batch import from a .txt (§7 "parked") · other languages (English only, decision; `docs/TEXTS.md` ready) · more keyboard shortcuts ("no useless shortcuts") · a picture on each row (model D, the row grammar) · saved passwords (decisions 9 and 36) · Pause (Stop + Continue already resume).

## Where we are ahead of all six

Errors explained with evidence (decision 38) · log-in inside the app, one site at a time · sign list from GitHub with "What changed" · tool updates with "Update and retry" · the Console with its command box · 4 pieces at once by default and the card's reading reused.
